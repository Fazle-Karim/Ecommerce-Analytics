# E-commerce Sales & Customer Analytics

An end-to-end data analytics project analyzing ~100,000 real orders from the
Olist Brazilian E-commerce marketplace (2016–2018). The deliverable is a
multi-page Power BI report backed by a clean SQL Server data warehouse and a
proper star-schema model.

---

## Business Context

**Primary audience:** Head of Sales and Marketing.

**Goal:** Answer 6 core business questions about revenue performance, product
& regional growth, customer value, retention, logistics quality, and seller
performance — turning raw transactional data into actionable insights.

---

## What Was Built

- **Raw layer** — 9 CSVs loaded into SQL Server with row-count reconciliation
  and append-only load log (`raw.load_log`).
- **Clean layer** — typed, deduplicated, category-translated tables with an
  append-only audit log (`clean.cleaning_log`).
- **Analytics layer** — star schema: `fact_orders`, `fact_order_items`,
  `dim_date`, `dim_customer`, `dim_product`, `dim_seller`, plus
  `customer_rfm` and `cohort_retention`.
- **bi schema** — slim views for Power BI (integer keys, no timestamps,
  RFM merged into `dim_customer`, cohort sentinel split out).
- **Control totals** — every expected value pinned in
  `documentation/control_totals.json`, generated by Python and verified by
  a separate script.
- **Test suite** — 143 checks across 5 SQL test files, all passing.
- **Pandas–SQL parity** — `EXCEPT` comparison proves SQL reproduces pandas
  cell-for-cell on all 94,703 RFM rows and 211 cohort cells.
- **Reproducible rebuild** — full pipeline runs from an empty database
  twice with identical results (`documentation/rebuild_evidence.md`).

## Dataset

**Source:** [Olist Brazilian E-commerce Dataset on Kaggle](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)

~100k orders, 9 relational tables, 2016–2018:
`orders`, `order_items`, `payments`, `reviews`, `customers`, `sellers`,
`products`, `geolocation`, `category_translation`.

**Verified data characteristics:**

- **Repeat customer rate:** 3.12% of 96,096 unique customers.
- **Customer identity:** `customer_id` is per-order; `customer_unique_id`
  identifies the person. All customer-level analysis uses the latter.
- **Referential integrity:** 100% clean across all 6 core foreign keys.
- **Payments:** 2.98% of orders have multiple payment rows.
- **Reviews:** 814 duplicate `review_id` rows; 768 orders (0.77%) have no review.
- **Order statuses:** 97.02% delivered. GMV excludes canceled, unavailable,
  created.
- **Date coverage:** Effective analysis window is 2017-01 → 2018-08.
- **Geolocation:** 1,000,163 rows collapse to 19,015 unique zip prefixes.

See `documentation/data_quality_log.md` for the full log. All numbers are
pinned in `documentation/control_totals.json`.

---

## Key Findings

- **Customer concentration:** Only 3.12% of customers place a second order.
  Champions (F≥2, R≥4) are 1,229 customers — 1.3% of the base.
- **Late deliveries hurt reviews:** Average score drops from 4.29 (on-time)
  to 2.27 (late), a **−2.02 point** gap. Late orders are also under-reviewed
  (2.3% no review vs 0.5% for on-time).
- **2018 plateau:** Marketplace grew through 2017, plateaued around March
  2018, and declined ~10–15% by August. Caveat: only 8 months of 2018 data.
- **Payments reconcile cleanly:** `SUM(payment_value)` matches
  `SUM(price + freight)` to within 0.0176%, with residuals concentrated in
  credit-card installment orders.
- **Seller concentration:** 3,029 sellers in the analytic population; the
  top 10% drive the bulk of revenue.

## How to Reproduce

1. Clone the repo.
2. Install SQL Server + SSMS.
3. Download the Olist CSVs from Kaggle into `C:\data\olist\`.
4. Run scripts in order in SSMS (SQLCMD mode ON):
   - `sql/01_raw_tables.sql`
   - `sql/02_load_raw.sql`
   - `sql/03_cleaning.sql`
   - `sql/test_expected_values.sql`
   - `sql/tests/03_cleaning_tests.sql`
   - `sql/04_dimensions.sql`
   - `sql/05_facts.sql`
   - `sql/tests/05_facts_tests.sql`
   - `sql/06_rfm_cohorts.sql`
   - `sql/tests/06_rfm_cohorts_tests.sql`
   - `sql/07_bi_views.sql`
   - `sql/tests/08_bi_views_tests.sql`
5. Run Python scripts from the repo root to regenerate reference files
   and coverage.
6. Open the `.pbix` in Power BI Desktop and refresh.
